# Solo publisher

Writes infrequently, roughly monthly, to a small list, entirely by hand in the browser editor. Rarely opens Settings after initial setup. Cares about two things: does the post look right, and did it actually go out.

**Stresses:** the editor/preview loop, the schedule/cancel review window, the dashboard's at-a-glance state.

## Onboarding

1. Follow the setup guide (`docs/setup/`) to deploy a fresh instance.
2. Open the dashboard for the first time: empty subscriber list, default template, no sent history.
3. Set publication identity (name, tagline, logo) in Settings.
4. Subscribe themself as a test, confirm via the email link, watch the subscriber count move to 1.
5. Write and send a first post (see Steady state, below), watching for anything that reads as broken specifically because everything is empty or default the first time through.

## Steady state: write and send a post

1. Drafts → New post.
2. Write subject and Markdown body, watch autosave settle.
3. Switch to Preview, spot-check formatting.
4. Send a test email to their own inbox, check it in a real client.
5. Schedule; the review window opens.
6. Optionally cancel or reschedule while the window is still open.
7. Fire time passes; check the Sent page and confirm the delivered count.

## Steady state: check on an old post

1. Open the Sent page.
2. Find a post from a few weeks back, open its record.
3. Skim delivery outcomes for anything that looks wrong: a bounce, a complaint.
